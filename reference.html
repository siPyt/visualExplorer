Chapter 1: Three Equipment Tiers & Module Scan Heartbeat Architecture & Execution Order

3 DeltaV Control Tiers
Official DeltaV		 Unit Phase (ISA-88: EPH) = owns batch recipe states (RUN, HOLD, RESTART, STOP, ABORT, FAIL_MONITOR). Equipment Module (EM) = coordinates a team of devices for one process job; almost never wires to physical I/O cards. Control Module (CM) = owns ONE physical field device (valve, pump, scale, loop). AI Mental Model: Recipe Boss → Team Coordinator → Single-Device Worker.
Standard EM Handshake Parameters
Official DeltaV		 A_COMMAND = requested command/state (Named Set MUST include 255 = Idle). A_TARGET = command currently executing. A_PV = confirmed completed command/state (stays Idle until finished without error). Top boundary between Unit Phase and EM (7009 p. 462).
EM ↔ CM Boundary
Official DeltaV		 EM writes down to module-level CAS_SP.CV (wired inside CM to DC1/CAS_IN_D) and reads back physical proof on PV.CV (wired from DC1/PV_D) or analog AI1/OUT.CV & .ST. Never confuse outbound command (CAS_SP) with field proof (PV).
Scan Rate & Execution Order (#1 → #2 → #3)
Official DeltaV		 EMs scan on a fixed heartbeat (typically 500 ms or 1 s). Screen position means NOTHING—FBD blocks solve strictly by their bottom-right badge (#1, #2, #3). Main → Module → Properties (Scan Rate); Edit → Execution Order.
Dashed Feedback Wire Rule
Official DeltaV		 In real DeltaV, a dashed/dotted wire does NOT mean discrete! It appears only when the source block executes after the destination block (e.g., #3 → #2)—meaning a 1-scan delay (CONFIG p. 368). On-Line, Bold wire = non-zero value; thin wire = zero/False.
PRECLOSE_LEAD
Official DeltaV		 Commands the feed valve closed early (e.g., 15 kg before target) to compensate for pneumatic valve stroke time (1–3 s) + module scan latency so in-flight liquid doesn't overfill the tank. Used in CND3 (REMAINING_WT <= PRECLOSE_LEAD).
Chapter 2: 1 Outer Algorithm vs. 4 Inner Patterns & Unwired Boxes Reading Any Sheet Cold

4 Core EM Algorithms
Official DeltaV		 Pick ONE outer container when building an EM (dropdown shows 7 total incl. 3 phase hybrids): 1. Command-Driven (multi-step SFC per command), 2. State-Driven (Items × States table, ZERO SFCs!), 3. FBD (continuous blocks only), 4. SFC (single standalone sequence). Check Hierarchy View or Main → Module → Properties.
4 Inner Patterns
AI Mental Model		 ONLY Pattern 1 steps through time! Patterns 2, 3, and 4 solve continuously every Scan: P1 = Step/State Flow; P2 = Permissives & Interlocks; P3 = Mode & Setpoint Routing; P4 = CM Command & Feedback. Command EMs usually use all 4 (3 if discrete); State-Driven EMs fold P1+P3+P4 into one table (2–3 total). Don't wait for an SFC step to understand an interlock—P2 solves every Scan!
True FBD Pin Layouts
Official DeltaV		 CND: OUT_D ONLY (zero input pins!). ACT: IN_D ONLY (zero output pins!). XFR: IN_1 (0), IN_2 (1), SELECTOR → OUT (underscores! No "BSEL" block in DeltaV!). CALC: IN1..16 → OUT1..16 (no underscores!). CND reads refs in its expression; ACT writes := every scan while IN_D = True.
Subordinate vs. Standalone CMs
Official DeltaV		 Subordinate (Nested) CM lives inside the EM tree (path '^/CM_NAME/...'). Standalone / Shared CM sits alongside the EM in the Plant Area so multiple EMs can share it (path '//CM_NAME/...'). Check DeltaV Explorer → Control Strategies → [Area].
5 Unwired Box Types & Module Level
Official DeltaV		 Unwired boxes are NOT unused! Know all 5: (1) Internal Reference (front-door tunnel like MODE → PID1/MODE—required by State-Driven tables & GEM faceplates!), (2) External / Dynamic Ref, (3) Module Vars / TPs, (4) Parameter Shortcut ($) (e.g., PID1$GAIN—preserves Class link!), (5) Status Outputs. View → ☑ Parameter View → read Connection type & Parameter type. Class rename fix: click Default Name!
Hollow Square □ Pin Side Compass
Official DeltaV		 On an unwired box: □ on the RIGHT edge ([ PARAM □ ]) = Input/Setting coming INTO the module (cause). □ on the LEFT edge ([ □ PARAM ]) = Output/Result going OUT of the module (symptom). Instant 1-second compass on zero-wire PCSD diagrams!
Chapter 3: Operating Modes, DC Safety Pins, Status (.ST) & Syntax Most Tested Plant Rules!
Thing to Memorize What You Need to Memorize About It Click Path / Plant Rule
DC Block Mode Rule (NO MAN!)
Official DeltaV		 Discrete DC blocks (valves/motors) support ONLY AUTO and CAS as selectable target modes (FBR p. 427): AUTO = operator faceplate control (ignores EM CAS_IN_D!); CAS = obeys upstream EM. (MAN only exists on PID/AO/DO!) ST Write: '//CM_FEED_XV/DC1/MODE.TARGET' := CAS; (short: '//CM_FEED_XV/MODE.TARGET' := CAS;). Check: '//CM_FEED_XV/DC1/MODE.ACTUAL' = CAS!
LO vs. OOS
Official DeltaV		 LO (Local Override, Purple HMI border) = automatic safety shield (never a selectable target); block stays alive & forces safe output. OOS (Red ✕, spelled OS in ST expressions!) = manual maintenance lockout; block stops solving and stamps Bad: Out of Service. In Structured Text expressions, always spell Out of Service as OS (never OOS).
All 4 DC Safety Pins + Polarity Split
Official DeltaV		 MEMORIZE THE POLARITY FLIP (FBR pp. 419–427):
• Active-HIGH (= 1 triggers LO): SHUTDOWN_D (ALWAYS active, NOT optional → Passive) & TRK_IN_D (local HOA hand switch → OUT_D := FV_D).
• Fail-Safe LOW (= 0 triggers LO): INTERLOCK_D (stops running device AND blocks start) & PERMISSIVE_D (START-ONLY while Passive — NEVER trips a running motor!).
• 5th Cause of LO: DC_STATE = Locked waiting for RESET_D pulse.		 Diagram View → click DC1 → Parameter View → double-click DEVICE_OPTS.
SP Track × Reset Required Trap
Official DeltaV		 • Both OFF: Clearing trip causes instant unattended auto-restart!
• Reset Req ON only (FBR p. 421): Latches Locked (LO), but pulsing RESET_D still auto-restarts because SP_D stayed START!
• SP Track ON only: Overwrites SP_D := STOP during LO; stays stopped on clear.
• BOTH ON (Gold Standard): Stays Locked (LO) AND overwrites SP_D := STOP → pulsing RESET_D unlocks cleanly and stays stopped!		 Test live in Visual Explorer Module 8: CM_PMP_101.
.ST Status Ranges & >= GOOD Rule
Official DeltaV		 Status integers: 0..63 = BAD (Red ✕), 64..127 = UNC (Blue ?), 128..191 = GOOD (GoodNonCascade), 192..255 = GoodCascade. NEVER write .ST = GOOD (fails on healthy cascade signals!)—always write .ST >= GOOD and .ST <= BAD! CONFIG p. 81. Also remember: CALC outputs default to GOOD unless you write 'OUT1.ST' := 'IN2.ST';!
DeltaV ST Syntax & Path Rules
Official DeltaV		 • Single quotes '...' wrap paths & Named Sets ('vlvnc-sp:OPEN').
• Prefixes: //MOD/... (external), ^/PARAM (up 1 level), /PARAM (module root), /+/PARAM (phase).
• = asks a Yes/No question (CND/Transitions); := writes a value (ACT/CALC/SFC Actions).
• Mode/Status keywords (OS, MAN, AUTO, CAS, LO, GOOD, BAD, UNC) are UNQUOTED.		 Never write .ACT—always write .ACTUAL. In DC1: STATE_MASKS empty=0, check=1, light-gray=don't care.
Chapter 4: Pin-by-Pin Command-Driven EM (EM_TANK_CHARGE) SFC + Continuous FBD Partnership
Thing to Memorize What You Need to Memorize About It Click Path / Plant Rule
SFC Qualifiers [P] vs. [N]
Official DeltaV		 [P] (Pulse) = runs on 1st scan of the step ONLY (mandatory for START_WT.CV tare snapshot! Using [N] makes tare chase gross weight forever → overfill!). [N] (Non-stored) = runs every scan while step is active; written := values RETAIN their last value after the step ends! Double-bordered box = Initial Step; elapsed seconds print under every step On-Line; Termination (═╧═) sets A_PV.
Permissive vs. Interlock Split
Official DeltaV		 Strip A (CND1 Permissive) = Front-door bouncer checked ONLY at T10_START_OK before starting. Strip B (CND2 → ACT1 Interlock) = Emergency brake scanning continuously during the charge; executes '//CM_FEED_XV/CAS_SP.CV' := 'vlvnc-sp:CLOSE'; and '^/FAIL_REQ.CV' := 1; immediately without waiting for any SFC transition! Double-click CND On-Line to open the green ✓ / red ✗ Expression tree.
XFR1 → CALC1 → CND3 Chain
Official DeltaV		 XFR1 (#1) chooses Local (IN_1) vs. Recipe (IN_2) target → CALC1 (#2) computes NET_WT := IN2 - IN3, OUT1 := IN1 - NET_WT, AND 'OUT1.ST' := 'IN2.ST'; → CND3 (#3) checks REMAINING_WT <= PRECLOSE_LEAD AND .ST >= GOOD for T20_PRECLOSE. Must solve #1 → #2 → #3 in same scan (solid wires, zero dashed delay!).
TIME_DURATION vs. DC1/FAIL_ACTIVE
Official DeltaV		 CND4 confirms physical limit switch (PV = 'vlvnc-pv:CLOSED'); CND5 uses built-in TIME_DURATION = 10s so normal 2-second valve stroke never false-alarms. Inside the child CM, DC1 has its own confirm timers (CFM_PASS_TIME, CFM_ACT1_TIME) setting FAIL_ACTIVE = True. Step timer syntax in transitions: 'S20_TRIM_CLOSE/TIME.CV' >= 5.
Chapter 5: Phase Hold, Restart, Abort & The Golden Tare Rule Preventing Batch Overfills
Thing to Memorize What You Need to Memorize About It Click Path / Plant Rule
Where Hold / Restart / Abort Live
Official DeltaV		 RUN_LOGIC, HOLD_LOGIC, RESTART_LOGIC, STOP_LOGIC, ABORT_LOGIC, and FAIL_MONITOR are Unit Phase composite states—NOT standard EM states (7016 pp. 70, 202). Any non-zero failure in FAIL_MONITOR automatically sends the Phase to Holding. DeltaV Explorer → Library → Phase Classes → open in Control Studio → Hierarchy View.
The Golden Tare Rule
AI Mental Model		 Snapshot START_WT.CV ONCE on initial charge start via [P]. NEVER re-tare inside RESTART_LOGIC! Re-taring after Hold resets NET_WT to 0 and pumps a full new batch on top of what was already added (e.g., 120 heel + 200 delivered + 500 re-poured = 200 kg overfill!). Audit RESTART_LOGIC: confirm zero steps overwrite START_WT.CV or zero out totalizers.
Safe Recovery Sequence
Official DeltaV		 HOLD_LOGIC closes valve & preserves locked START_WT.CV. RESTART_LOGIC stays blocked by CND1 while fault (.ST = BAD) is active; once cleared to GOOD, resumes finishing only REMAINING_WT. ABORT_LOGIC stops all outputs and requires full Reset to S0_IDLE. Test in Visual Explorer: EM_TANK_CHARGE Workshop 5.

Chapter 7: State-Driven Equipment Modules (EM_XFER_HDR & EM_2STAGE_VLV) Items × States Table (Course 7016)
Thing to Memorize What You Need to Memorize About It Click Path / Plant Rule
ZERO Graphical SFCs!
Official DeltaV		 State-Driven EMs have NO SFC steps or transitions—they use an Items | States spreadsheet alongside the continuous FBD sheet (7016 p. 140). AI Mental Model ("3-in-1 Table"): One grid bundles Patterns 1, 3 (MODE.TARGET rows), and 4 (Write + Readback), leaving only Pattern 2 safety/watchdogs on the FBD sheet. Click the State Table in Hierarchy View for the grid; click Diagram View for FBD watchdogs.
Module-Level Paths ONLY
Official DeltaV		 Every State Table row's Write & Readback path must be module-level (CM/CAS_SP.CV → CM/PV.CV; CM/MODE.TARGET → CM/MODE.ACTUAL)—deep block paths like /DC1/MODE are forbidden! (That's why the unwired MODE Internal Reference box in Ch. 2.5 is mandatory!) = Cascade/ or = Auto/ means "write this value AND verify Readback matches."
A_PV Confirmation & (not written) Cells
Official DeltaV		 A_PV drops to Idle (255) whenever any checked row's Readback disagrees (jammed valve or operator in AUTO). Unchecked (not written) cells neither write nor check readback—used in Auto Mode to hand valves back to operators without slamming them shut, and in Idle (255)! Quick rule: timed stages = Command-Driven; instant lineup = State-Driven.
Chapter 8: Analog Control Modules, PID Loops & Back-Calculation (FIC_101) Continuous Plant Foundation
Thing to Memorize What You Need to Memorize About It Click Path / Plant Rule
Standard Loop Flow & Direction
Official DeltaV		 AI1 (#1) scales 4–20 mA → EU (keep L_TYPE = Indirect for custom OUT_SCALE) → PID1 (#2) computes 0–100% OUT → AO1 (#3) drives 4–20 mA valve. Reverse-Acting (default) = PV drops below SP → OUT goes UP; Direct_Acting = PV rises → OUT goes UP. FBR p. 232 trap: If PID1 has both IO_IN and wired IN, IO_IN wins!
All 8 PID Operating Modes
Official DeltaV		 Selectable Targets: OOS (only mode where CONTROL_OPTS/STATUS_OPTS can be edited!), Man (operator types OUT %), Auto (operator types SP), Cas (follows upstream Master PID), RCas/ROut (supervisory).
Automatic-Only (Never Selectable): IMan (downstream not in CAS) and LO (TRK_IN_D = True).		 Bad PV Mode Shed (FBR p. 240): Bad AI1 sheds AUTO → MAN (check Target to Manual if Bad IN to stop auto-resume!).
BKCAL_OUT → BKCAL_IN Feedback Wire
Official DeltaV		 Drawn gray dotted because AO1 (#3) feeds back to PID1 (#2) (next scan). Carries 4 statuses:
• Non-Limited = normal control.
• Limited High/Low = valve clamped at 100%/0% → freezes integral (zero windup!).
• Not Invited = downstream in MAN → forces PID1 to IMan tracking actual valve % (bumpless return!).
• Bad: OOS = downstream offline → holds IMan.		 2:00 AM Rule: See PID = IMan? Trace gray dotted BKCAL_IN downstream!
Field Traps (AO, HART, DVC, KNL)
Official DeltaV		 • IO_OPTS: Increase to close inverts 4–20 mA for Air-to-Close (fail-open) valves.
• Fisher DVC Bad ConfigErr after swap → check AMS Input Range (defaulted to 4–20 mA instead of %!).
• HART_FIELD_VAL: leave EU blank unless intentionally re-ranging transmitter.
• Nonlinear gain KNL (pH loops) applies to P + I only — never D.		 CONTROL_OPTS / FRSIPID_OPTS live in PID1's bottom Parameter View.
Chapter 9: Cascade Control & CTLSL Override Control (CASCADE_201) Multi-PID Loops
Thing to Memorize What You Need to Memorize About It Click Path / Plant Rule
Master → Slave Cascade & Double BKCAL
Official DeltaV		 Slow Master (PID_TIC, AUTO) outputs a flow setpoint into fast Slave (PID_FIC, CAS) → AO_VLV (CAS), rejecting supply disturbances in seconds. Two gray dotted BKCAL wires (#4→#3 and #3→#2): putting Slave in AUTO drops Master to IMan; putting AO in MAN drops BOTH to IMan! Enable FRSIPID_OPTS: Dynamic Reset Limit on Master to prevent windup on upstream restrictions.
CTLSL (Control Selector) Override
Official DeltaV		 Picks LOW, HIGH, or MIDDLE of up to 3 PIDs (SEL_1..3). Why you MUST use CTLSL (never CALC/XFR): it has dedicated BKCAL_SEL1..3 outputs that clamp every standby PID right at the winning valve output so takeover is instant with zero windup! FBR p. 187 trap: If ANY connected SEL_1..3 goes Bad, CTLSL automatically sheds Auto → Man!
Chapter 10: Output Tracking, Selector Blocks & Composite Blocks Interlocks, ISEL & Composites
Thing to Memorize What You Need to Memorize About It Click Path / Plant Rule
Analog PID Tracking (TRK_IN_D / TRK_VAL)
Official DeltaV		 When TRK_IN_D = True (and CONTROL_OPTS: Track Enable checked), PID drops to LO and forces OUT := TRK_VAL. Check Track in Manual if the safety trip must override an operator in MAN. On AO, check FSTATE_TIME & FSTATE_VAL for Bad CAS_IN fail-safe. Single valve: TRK_VAL = 0%. Split-range Acid/Base: TRK_VAL = 50%!
XFR vs. ISEL vs. CTLSL
Official DeltaV		 • XFR: 2 analog inputs + discrete SELECTOR + BAL_TIME ramp (SP or 2-sensor switch).
• ISEL: Up to 4 redundant sensors (IN_1..4), MAX/MIN/MID/FIRST_GOOD/AVG, auto-ignores Bad or DISABLE inputs!
• CTLSL: Up to 3 PID outputs with BKCAL_SEL1..3 anti-windup feedback!		 Never mix these three up on an analog sheet!
Embedded vs. Linked Composites
Official DeltaV		 Embedded = lives only in this module (local edit). Linked = stored in Library (editing updates every module using it!). Internal Input/Output parameters become the outer block's visible □ pins. Right-click Composite in Diagram View → Drill Down (or double-click / expand in Hierarchy View).
Chapter 11: Real-Plant PCSD 32-Device EM (3WT-0001-NEUT) & Split-Range SPLTR Live Site Mastery
Thing to Memorize What You Need to Memorize About It Click Path / Plant Rule
PCSD Template Clutter Rule (_EM_CMD32_140)
Official DeltaV		 Mentally ignore unbound <Ignored> device stubs (DEV20–32 showing 3.40282E+38 & FAILURE=True are masked off by SM_18..32=False!), disabled commands, blank timers, and unused OP/TPs. Every Run SFC follows S0000–S0020 (boilerplate acquire) → S0100 (real work! + S0100R Restart branch) → S9900 (release). In completed OFF, A_COMMAND = Undefined is normal—read A_TARGET / A_PV!
MONITOR: Sentinel vs. Hold + AT Trick
Official DeltaV		 SENTINEL_MONITOR (SM_AT1/2) catches subordinate device failures; HOLD_MONITOR (HM_AT1/2) catches process failures (e.g., TMR1 90-min timeout) and trips COMMAND_00000 (HOLD). AT Counting Trick: count outputs showing 0 (configured) vs. ??? (unused)! HOLD_REQ = True releases device mode locks in OFF; OPR_CMD_MASK is a decimal bitmask of clickable HMI commands.
SPLTR (Splitter) Block & 50% Safe Track
Official DeltaV		 Splits 1 PID output (CAS_IN) across 2 outputs (OUT_1, OUT_2) with 2 back-calc inputs (BKCAL_IN_1/2) → BKCAL_OUT. Modes: OOS, IMan, Auto, Cas ONLY (NO MAN!). With IN_ARRAY = [0, 49, 51, 100] & OUT_ARRAY = [100, 0, 0, 100]:
• 0–49% = Acid (0% = 100% Acid!); 49–51% = Deadband (both 0%); 51–100% = Base.
• CRITICAL: TRK_VAL MUST be 50% (never 0%, which dumps 100% Acid!).		 Slope-Aware BKCAL: 1 AO in MAN lets the other side keep running while sending LimHigh/LimLow; BOTH AOs out of CAS → IMan!
Chapter 12: Control Studio Live Safety — HMI Icons, Downloads & Alarms Protecting a Live Plant

DeltaV Live GEM Icon Priority Masking
Official DeltaV		 Not Running (MSTATUS) hides BOTH Bad IO and Simulate Active; Bad IO (BLOCK_ERR) hides Simulate Active (SIMULATE). Other key icons: Mode (ACTUAL ≠ NORMAL), No Permit (PERMISSIVE_D = 0), Interlock Bypassed (BYPASSED), Interlocked (DC_STATE = Shutdown/Interlocked). Never assume Simulate is OFF just because you only see Bad IO!
Partial Download 3-Mode Truth Table
Official DeltaV		 • Preserve critical block values: Keeps live Mode, OVERWRITES user SPs back to offline DB!
• Preserve user-defined and critical block values: Safest—keeps BOTH live Mode and live SPs!
• Use configured values: WIPES BOTH Mode and SP back to offline DB defaults!		 Check Main → Module → Properties before downloading any live module!
Upload "Select None" & 2-Checkbox Cold Restart
Official DeltaV		 Upload Prompt: Clicking OK uploads ZERO parameters by default—explicitly check params to save live tuning! Cold Restart NVM Persistence: Must check BOTH parameter-level AND module-level "Restore parameter value(s) after restart" checkboxes! Missing either checkbox wipes operating setpoints to default on Cold Restart.
Dynamic Ref Limit & ALARMS[1]
Official DeltaV		 Never exceed 3 simultaneous Dynamic References in one SFC step (can drop Controller Free Time to ~0%!). ALARMS[1] exposes highest-priority active alarm (CRITICAL=15, WARNING=11, ADVISORY=7, LOG=3); CUALM=current, LAALM=latched, NALM=unack, OPSUP=suppressed; write 1 to ALARMS.F_MACK to ack all. Stagger >3 Dynamic Refs across steps in groups of 3 (Tips p. 40).
